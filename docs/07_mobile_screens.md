## 2. تطبيق الفنيين (T)

### 2.1 مبادئ التصميم (NFR-16، NFR-17)
- **أزرار كبيرة** (≥ 48dp، والإجراء الرئيسي بعرض الشاشة في الأسفل)، وتعمل بالقفازات.
- **وضع التباين العالي** للعمل في ساحة الورشة، ووضع داكن.
- **الإجراء التالي واضح دائماً:** شاشة المهمة تعرض زراً رئيسياً واحداً حسب الحالة (بدأت ← الاختبار ← إنهاء).
- **شريط الاتصال دائم** في الأعلى: متصل / غير متصل + عدد التغييرات المعلقة.
- **لا شيء يضيع:** كل إدخال يُحفظ محلياً فوراً دون زر "حفظ".

### 2.2 التنقل
**شريط سفلي بثلاثة تبويبات:** مهامي · السجل · حسابي. وأيقونة المزامنة في الأعلى (← T-11).

### 2.4 الحالات الخاصة بتطبيق الفني
| الحالة | السلوك |

| مرفقات المهمة غير محمّلة أثناء الانقطاع | تظهر المهمة مع إشارة "المرفقات غير متاحة دون اتصال" |

| مهمة أُلغيت أو أُعيد إسنادها | تختفي من "اليوم" مع إشعار، وتبقى في T-11 إن كانت لها تغييرات معلقة |
| انتهاء الجلسة أثناء الانقطاع | الإدخال المحلي مستمر، ويُطلب الدخول عند الإرسال فقط |
| ذاكرة الجهاز ممتلئة | تحذير قبل التقاط الصور، وحذف الصور المرفوعة من الجهاز تلقائياً |

## 3. سلوك المنصة

| البند | السلوك |
|-------|--------|
| الروابط العميقة | `app://` + روابط عامة (Universal/App Links) بنفس مسارات الويب. كل إشعار وكل رابط مشاركة يفتح الشاشة المعنية، أو يحوّل للمتجر إن لم يكن التطبيق مثبتاً |
| الإشعارات | FCM لـ Android و APNs لـ iOS. النقر يفتح الرابط العميق، والإشعارات المجمعة حسب الطلب |
| الاتجاه | RTL كامل بالعربية، بما فيه أيقونات الاتجاه (السهم، الرجوع)، ولا تُعكس الأرقام ولا الشعارات ولا الصور |
| حجم الخط | دعم تكبير خط النظام حتى 200% دون قص النصوص (NFR-15) |
| الإصدار الأدنى | الخادم يفرض الحد الأدنى (04 §4.1)، والتطبيق يعرض شاشة تحديث إلزامية أو اختيارية |
| الأمان | الرموز في Keychain/Keystore؛ إخفاء محتوى التطبيق في مبدل التطبيقات لشاشات الفواتير؛ لا لقطات للشاشة في شاشة رمز الاستلام (Android) |
| الأداء | فتح التطبيق للرئيسية < 2 ثانية على جهاز متوسط؛ الصور بأحجام مناسبة للشاشة من الـ CDN |
